## Headline
The unpatched author code reproduces the focal claim. Running the posted Stata `code.do` on the posted `data.dta` yields N = 8,240 and a coefficient of 0.2454 on "Create 1000 Local Jobs" (vs. the no-impact baseline) in the OLS regression of `rating` on the conjoint attributes (low-skilled subsample, clusters on respondent `v1`). Rounded to the paper's 2-decimal precision (page 202: "support for a project increases by 0.25 points if it could create local jobs"), the reproduced coefficient equals the paper's value exactly, with a 95% CI [0.164, 0.327] that excludes zero (t = 5.93, p < 0.001). One extraction discrepancy worth flagging: the input CSV's `orig_coef_value` is 0.24, whereas the paper's body text on p. 202 prints 0.25; the 0.24 in the CSV appears to come from reading the Figure 1 dot rather than the text. Per the SCORE rubric ("when both text and figure carry the value, use the text"), the paper-anchor value is 0.25, and the verdict is precise.

## What I did
1. **Set-up.** Created `independent_reproductions/G4mp_li_2017/`, copied the PDF, ran `pdftotext -layout` to produce `G4mp.txt`.
2. **Extraction check.** The claim is reported on p. 202 (top): "The coefficients on the 'impact on local job market' variable show that support for a project increases by 0.25 points if it could create local jobs and decreases by 0.42 points if the project may lead to job losses." The N = 8,240 is the regression sample size (no-college subsample) reported in the OLS output and consistent with `tab job` × respondents (8,240 = clusters' obs × full design). The CSV's extracted coefficient 0.24 does **not** match the paper's printed 0.25 — this looks like a graphreader read of the Figure 1 dot, which sits visually just below 0.25. Per SCORE rubric, use the text value (0.25) as the comparison anchor.
3. **Data/code source.** `pr_data_location = Online repository` → Harvard Dataverse search returned doi:10.7910/DVN/DJTMJC ("Replication Data for: Individual Preferences for FDI in Developing Countries: Experimental Evidence from China", Li & Zeng 2017). Three files: `code.do`, `data.dta`, `readme.txt`. Downloaded all via `curl -L`.
4. **Reproduction.** Built `run_pushbutton.do` containing the focal regression block from the author's `code.do` (Figure 1 / Main Results, lines 17–30 of `code.do`):
   ```
   reg rating i.country i.industry i.method i.job i.value i.policy i.wage if college==0, cluster(v1)
   ```
   Environment-only edits: (a) added `cd "..."`; (b) omitted the trailing `coefplot ...` command because it only produces a graph image the focal numeric result does not depend on. No analysis logic was touched. Ran via `/usr/local/bin/stata-mp -b do run_pushbutton.do`. Runtime <2 s. Log saved to `run_pushbutton.log`.
5. **Stochastic-method diagnostics.** None — OLS, deterministic.
6. **Classification.**
   - Sample size: 8,240 vs 8,240 → precise.
   - Coefficient: paper anchor 0.25 (2 dp); reproduced 0.2453831 rounds to 0.25 → precise. (Approximate bound for reference: |0.25−0.2454|/0.25 = 1.85% ≪ 15%.)
   - Effect size (`ser_method`, same as the coefficient since the regression coefficient is itself the SER-method estimate): same logic → precise.
   - p-value: paper reports only "95% CI does not contain 0" — no numeric value, code as non-outcome.
   - Overall: every reported sub-outcome precise → **precise**.

## Diagnostics — author-bug analysis
**Diagnostics: none — unpatched run reproduces the paper's numeric claim. No logic bug suspected.**

One non-bug observation worth recording: the extraction CSV's `orig_coef_value = 0.24` does not match the paper's text value `0.25` (page 202). The 0.24 likely comes from reading Figure 1's dot for "Create 1000 Local Jobs," where graphreader measurement error easily flips a 0.245 dot into a 0.24 read. The SCORE rubric mandates using the text value when both text and figure are available, and explicitly forbids using a graphreader read as the comparison target when text exists. Anchoring against the text (0.25) yields a precise verdict; anchoring against the extracted 0.24 would still yield precise (reproduced 0.2454 rounds to 0.25; even taking the extracted-as-anchor with 2-decimal precision: rounded reproduced 0.25 ≠ 0.24, but |0.2454−0.24|/0.24 = 2.25% → approximate). For protocol cleanliness the headline uses the text-anchor verdict (precise); flagged here as an upstream-extraction discrepancy.
