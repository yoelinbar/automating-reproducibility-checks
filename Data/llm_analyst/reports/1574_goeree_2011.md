The Fisher exact two-sided p-value computed by R's `fisher.test()` on the 3x2 contingency table (voting rules r=5, r=7, r=9) x (red, blue) constructed from Table V's "without communication" panel for red-signal counts 5–8 yields p = 2.148e-14 — bit-for-bit identical to the extracted value. ## What I did

1. **Set-up.** Created `independent_reproductions/1574_goeree_2011/`, copied `papers/1574.pdf` in, ran `pdftotext -layout` to produce `1574.txt`.

2. **Extraction check.** Located Table V on p. 910 (printed page) and the surrounding discussion on p. 911. Table V's "Without Communication" panel gives, for each number of red signals (rows) and each voting rule r ∈ {5,7,9} (cols), the percentage of red choices and (in parentheses) the cell N. For red signals 5–8 the cells are:
   - r=5: 56% (9), 100% (8), 100% (7), 100% (7) → 27 red of 31 total
   - r=7: 24% (25), 29% (31), 54% (24), 81% (11) → 37 red of 91 total
   - r=9: 0% (9), 0% (12), 0% (9), 0% (5) → 0 red of 35 total
   Total N = 31+91+35 = 157. The paper text on p. 910–911 says "a (nonparametric) Fisher exact probability test on group decisions rejects outcomes being identical across voting rules without communication when the number of red signals is 5–8 at conventional significance levels" — it does not print numeric values for chi-squared, exact p, or Cramer's V. The extracted statistics in the audit CSV are derived from the Table V counts.

3. **Data/code source.** No code archive was posted (`pr_code_available = No`; `pr_data_location = Publisher website`). Data is fully present in Table V of the PDF itself. Reconstructed the contingency table by hand from Table V; no external download needed.

   - `python3 run_chi2.py` (scipy `chi2_contingency` + `association` for Cramer's V) on the 3x2 table [[27,4],[37,54],[0,35]].

5. **Stochastic-method diagnostics.** None — Fisher's exact and Pearson chi-squared are deterministic on a fixed contingency table. R's `fisher.test` for a 3x2 table uses Fisher's network algorithm exactly (no Monte Carlo).

One minor note worth surfacing (not a bug): the audit CSV's `orig_stat_type = chi_squared` with `orig_stat_value = 51.646` and `orig_p_value = 2.148e-14` mixes two different tests. 51.646 is the Pearson chi-squared statistic; 2.148e-14 is the Fisher exact p-value, *not* the chi-squared p-value. The chi-squared distribution p-value for X² = 51.646 with df=2 is 6.099e-12, three orders of magnitude larger than the Fisher exact p-value (though both are vastly significant). The paper itself only mentions the Fisher exact test by name. This is a coding choice in the extraction, not a numerical disagreement — no impact on the verdict.
